## 一、架构决策记录（ADR）

> 每条含 **状态**（已锁定产品方 / 暂定 / 已废弃）、**提出者**、**理由**。
> 实现者不得更改已锁定项；需变更时新增 ADR 并标注取代关系。

### ADR-001 · 复用通用 Agent Loop，不另起引擎
- 状态：已锁定（产品方） | 提出者：产品方
- 决策：mastery 能力 = 通用 Agent Loop + 专属提示词包 + 挂载 mastery 工具集。"收窄" = 工具白名单 + 模式门控 + 屏蔽无关工具。
- 理由：另起引擎会丢掉成熟的工具调用解析、上下文预算、问答草稿。

### ADR-002 · 双轨制：前沿（frontier）与分数（score）分离
- 状态：已锁定（产品方） | 提出者：产品方
- 决策：系统评估通过 → 推进 frontier **且**写 `mastery_levels`（`system`）；学习者声明 → 仅推进 frontier，`learner`，**不写分数**。
- 实现：`is_mastered = is_assessed_mastered OR override`；**单调度器**，用 provenance 播种 `RepetitionState`。

### ADR-003 · 知识点类型 MVP 创建后只读
- 状态：已锁定（产品方） | 提出者：产品方
- 决策：不允许原地改类型；要改只能删除重建。级联重置延后。

### ADR-004 · 大纲重建只做显式重置
- 状态：已锁定（产品方） | 提出者：产品方
- 决策：重建必须显式确认并说明损失；**禁止静默重建**；**不做**语义指纹继承（MVP）。

### ADR-005 · 模式→工具映射 fail-closed 分类 + 守卫 + 启动断言
- 状态：已锁定（产品方，本次回签） | 提出者：实现方
- 决策：分类表为**代码静态表**，**默认 fail-closed**（未声明即拒绝）；守卫只覆盖 mastery 固定工具集；**测试守卫 + 启动期断言**双保险。
- 理由：门控是不变量，必须完备、可测、fail-closed——关键不是"代码 vs 配置"，而是"未声明即拒绝"。

### ADR-006 · 存储用 SQLite + CAS
- 状态：已锁定（产品方，本次回签） | 提出者：实现方
- 决策：path 聚合落 workspace 级 SQLite；写经 `mutate()` 且以 `version` 做 CAS。
- 理由：per-path JSON 存在两会话丢更新（deeptutor 已亲历）；且需跨 path 查询与并发正确性。

### ADR-007 · 掌握门槛按类型分支
- 状态：已锁定（产品方） | 提出者：产品方
- 决策：`memory`/`procedure` 量化（`≥0.9`）；`concept`/`design` 定性（`mastery_assess`）。

### ADR-008 · 判分确定性，答案只存服务端
- 状态：已锁定（产品方） | 提出者：产品方
- 决策：注册时固定全部参照物；判分时刻不调用 LLM；面向学习者的投影不含 `expected_answer`/`explanation`。

### ADR-009 · 调度算法 SM-2 起步（显式二选一）
- 状态：已锁定（产品方） | 提出者：实现方
- 决策：M5 用 **SM-2**；**禁止** SM-2 字段与 FSRS 字段混用（选 SM-2 时 `stability/difficulty` 仅展示或删除）。详见 `04-scheduling.md`。

### ADR-010 · prerequisite_ids 为硬门控
- 状态：已锁定（产品方采纳） | 提出者：实现方
- 决策：前置未全部掌握时，该 KP 不进入 `next_objective` 且不可被评估。这是"混合类型靠拆分"能成立的开关。见 `INV-27`。

### ADR-011 · 缺口处理：先分类再路由
- 状态：已锁定 | 提出者：实现方
- 决策：缺口分**目标缺口 / 来源遗漏**，且再分"生成漏了 / 来源没有"；前者可"重新生成"（受 ADR-004 约束），后者只能"接受缺口"或"补来源"。**禁止静默重建/静默丢弃**。见 `06-tools-contract.md`。

### ADR-012 · CAS 混合策略：有界重试 + 前置失败冒泡 + 耗尽冒泡
- 状态：已锁定 | 提出者：实现方
- 决策：乐观版本冲突自动重试 ≤3 次（抖动退避）；前置条件失败抛 `PreconditionError`（永不重试）；耗尽抛 `ConcurrentModificationError`。见 `INV-11a/b/c`。

### ADR-013 · 判分幂等键 = `(path_id, interaction_id)`
- 状态：已锁定 | 提出者：实现方
- 决策：`interaction_id` 注册时生成、与题 1:1；`session_id`/`turn_id` 仅审计，不参与幂等；终态事务保留可查。

### ADR-014 · 供应商无关分层
- 状态：已锁定 | 提出者：实现方
- 决策：**领域层（`learning/*`）零耦合**供应商；Loop 层经 `LLMClient` 适配器隔离；提供 fake 客户端供离线测试。供应商决策 deadline = **M2 接 Loop 前**。见 `05-api-contract.md` §运行时边界。

### ADR-015 · 模式切换审计为 session 级，含 actor
- 状态：已锁定 | 提出者：实现方
- 决策：成功切换记 `mode.changed`（session 级，不入 path 聚合），含 `actor∈{learner,tutor}`；被拒切换默认不持久。见 `02-mode-tool-matrix.md`。

### ADR-016 · 地图语义：权威、可编辑、可版本化、**近似**；真相源 ≠ 编辑权限
- 状态：已锁定（产品方，本轮采纳） | 提出者：产品方
- 决策：地图是**唯一权威来源**（进度从掌握度推算），但它是**可版本化的近似草案**，不是先验完备的真理。
  把"**真相源**"与"**编辑权限**"解耦：权限只约束"**改结构**"（增删改模块/KP），不约束"**记录**"。
- 理由：真实学习是涌现的——中途会发现缺口、新前置、目标漂移；要求"停下切 outline 才能记一笔"是把一致性代价转嫁给学习动作。

### ADR-017 · 学习中"捕获-延后"通道（capture-and-defer）
- 状态：已锁定（产品方，本轮采纳） | 提出者：产品方
- 决策：study/review 模式下允许 `mastery_propose_objective`（提议候选 KP）与 `mastery_note_gap`（记缺口），**只写候选/备注，不改地图结构、不影响门槛**；下次 outline 时批量 reconcile（accept→走 revise 成为 KP，reject→丢弃）。见 `INV-53/54`。

### ADR-018 · 大纲生成质量量化（覆盖报告 + `outline_eval`）
- 状态：已锁定（产品方，本轮采纳） | 提出者：产品方
- 决策：`build` **必须返回覆盖报告**（covered/total/missing/reported）；新增 **golden-set 评测**（确定性指标优先：coverage、grounding、无环、计数区间；语义指标用嵌入匹配 Precision/Recall），可复现、可对比基线；在线代理指标 = **编辑率/重建率**。见 `09-outline-eval.md` / `INV-56/57`。

### ADR-019 · 导师行为契约 + 确定性守卫
- 状态：已锁定（产品方，本轮采纳） | 提出者：产品方
- 决策：每模式写明**允许意图 / 前置证据 / 禁止项 / 拒绝文案 / 预算（回合·工具·追问·提示）**；**能进引擎的都进引擎**（不靠提示词）；来源纪律：不得为未接地 KP 声称来源支撑。见 `08-tutor-behavior.md` / `INV-58/59/60`。

## 二、UI 形态约束

```
UI 形态：⚠️ 暂定，M7 前确认。
约束：M1–M6 不得依赖任何具体 UI；但 UI 无关契约必须在 M2 前定。
```

- **UI 无关契约（现在必须定）**：`INV-18/19/20`、异常冒泡（`ConcurrentModificationError`/`PreconditionError`）、`ungrounded` 可见性、`mode.changed` 的 `actor`。
- **暂不定**：Web/CLI/桌面/语音、页面结构、组件库、路由、交互细节。
- **"伪 UI 决策"必须现在定**（否则 M7 补就是破坏性变更）：

| 看起来像 UI | 实际是 | 落点 |
| --- | --- | --- |
| 未接地 KP 角标 | 领域状态可见性 | `INV-24`、`grounding` 可查询 |
| 场景切换按钮 | 场景变更语义 | `INV-20`（只影响新条目） |
| 复习量翻倍提示 | 调度参数后果 | `desired_retention` 与复习量关系可计算 |
| 冲突提示 | 异常契约 | `INV-11b/c` |

## 三、供应商与运行时边界（摘要）

- M1 全为无 LLM 的纯逻辑 → **无需选供应商**。
- 三个入口：主导师模型（M2 前定）、Task Model（M3+）、嵌入/检索（M2/M3，若做缺口检测）。
- `provider 无关` = 领域层零耦合 + Loop 经适配器隔离。
- **已确认**（M2 前）：主导师模型 = **DeepSeek**；工具调用 = **原生 function calling**；streaming = **WS 事件**；Task Model 一期**回退主模型**；嵌入 = **bge-m3**（可选二期）。

## 五、Definition of Ready（交给实现 AI 的准入条件）

任何任务必须**同时**具备：**接口签名 + 不变量 + 验收测试**。缺一视为赌 AI 猜对。

## 六、Definition of Done（里程碑通用）

- 关联合约测试全部通过；
- 追踪表（`03`、`04`、`05`、`06`）中对应 `INV-xx` 均有测试覆盖；
- 不引入未经 ADR 批准的新依赖或新实体；
- 纯函数层可离线测试。
