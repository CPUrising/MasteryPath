# MasteryPath 规格包 · README

> 本目录是「MasteryPath（精通之路）」智能体的**契约层规格包**——不是代码，是**判定代码对错的依据**。
> 任何实现者（人或 AI）都应以本包为准：**对错由验收测试（TC）判定，而非口头理解。**

## 一、这是什么、不是什么

- **是**：实体定义、不变量（INV）、架构决策（ADR）、接口契约、验收测试（TC）。
- **不是**：代码、UI 设计稿、可运行的脚手架。
- **产出目标**：让不同实现者（甚至不同模型）产出的代码都能被同一套 TC 判定。

## 四、约定（命名与编号）

| 类型 | 格式 | 例 |
| --- | --- | --- |
| 不变量 | `INV-<两位数>` | `INV-04`（量化门槛） |
| 验收测试 | `TC-<分组字母><序号>` | `TC-B4`、`TC-K3` |
| 架构决策 | `ADR-<三位数>` | `ADR-006`（SQLite + CAS） |
| 工具 | `mastery_*` | `mastery_quiz` |

分组字母：A 模型、B 存储/CAS、C 门槛、D 门控、E 交互、F 阈值/前置/缺口、G 调度、H 判分、I API/事件、J build/revise、K quiz/grade、L 模式审计。

## 六、变更流程（重要）

1. **ADR-first**：任何决策变更先写 ADR，再改正文；**禁止就地改值而不留痕**。
2. **不变量是硬约束**：改门店前先确认它不破坏任何 `INV-*`。
3. **测试即契约**：新增/修改行为必须配 `TC`；否则视为未完成。
4. **默认值可追溯**：凡数值/选项，必须能追到 `07` 的回签行。

## 七、与实现者（含 AI）协作的准入条件

> **Definition of Ready**：任务只有同时具备 **接口签名 + 不变量 + 验收测试** 才算"可交付"。缺一，视为让实现者猜。

- 交付前对照对应文档的 **DoD**；
- 实现者**不得引入**未经 ADR 批准的新实体/依赖；
- 纯函数层（policy / mode）必须**离线可测**（无网络、无 LLM）。

## 九、一句话

> **ADR 定决策，INV 定约束，TC 定对错**；这套包不解释"怎么做才对"，它只规定"做完了怎么被判为对"。
